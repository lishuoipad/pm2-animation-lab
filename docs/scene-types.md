# 扩展场景与后台取帧

0.2在原25项请求之外新增`pm2_scene_comparison_request/v1`。仍由`pipeline`发布并复核，GIF/MP4编码复用活动比较模块，不另设播放入口。旧请求格式和25项档案不变。

旅行年龄边界为`<=11`、`<=13`、`<=15`、其余；季节为1春、2夏、3秋、4冬。自由行动的`conditions`是`{"mode":"free"}`或`{"mode":"observe"}`。旅行是`{"age":17,"season":3,"destination":"mountain"}`，目的地也可为`sea`。它们是一张插画在观察区间内持续显示，没有自行补出的肢体动作。

东部地图视区为28×24个16×16图块，原生画面位置(64,48)。源码保留的右上角一列八行用于非地图界面，比较将这块区域显式标灰，并在清单记录排除矩形；其余169,984像素全部核对。世界位置变化才切换两相步态；站立等待不会自行走路。地图初始状态包含`map_x/map_y/girl_x/girl_y/direction/phase/terrain_phase`，后续每步是`dx/dy/scroll_x/scroll_y/terrain_phase`。单位步长、地图边界、状态顺序均校验。它是表现重建，不模拟碰撞决策、随机遇敌、地图事件、战斗或存档推进。

## 后台运行原游戏

默认研究方式是后台libretro核心。需要自备核心、M3U及其引用的游戏归档/覆盖包、锚点存档和核心配置；所有文件都在显式外部数据根内并绑定SHA-256。此命令不会操作桌面鼠标，也不会下载模拟器。当前输入适配器只接收模拟器鼠标位移和左右键；键盘请求会被拒绝。

```sh
pm2-animation-lab capture --request /external/requests/capture.json --output /external/captures/new-run --quarantine-root /external
```

请求结构见`examples/native-capture.template.json`。`boot_frames/settle_frames`明确规定启动和恢复后的运行步数。`actions`依次执行，每项`op`为`step`或`record`；`frames`是运行的核心帧数，`mouse`的字符串键`0/1`是每帧dx/dy，`2/3`是左右键0或1。移动一次通常使用`frames:1`；`release:true`清空按键后再运行10帧。必须且只能有一次`record`，从该操作起记录每一帧，不能中途丢帧。每项最多3600帧，总操作量有上限。

输出包含完整640×480RGB图像、逐帧索引、每一步截图/操作回执、输入绑定和运行器快照。核心报告的浮点频率以精确有理数倒数保存，避免累计舍入。它表示模拟器报告的节拍，不是采集工具的墙钟耗时，也不证明另一台机器、另一核心或另一前端的原速。当前原生实验证据来自Windows DOSBox Pure 1.0-preview6；其他系统能否实际运行自备核心需要单独核验。

本机相同锚点、配置和65步输入重放后，3097/3097完整原生帧RGB与顺序相同。这个结论与321帧场景合成核验是两项不同证据。

## 冻结观察与统一发布

新请求包含`scene/conditions/archive/palette/observation/encoder`的明确值或文件绑定。`observation`使用`pm2_scene_observation/v1`，引用`capture.json`，记录`first_frame/end_frame_exclusive`、按序的`states`、`scope_note`及先行冻结区间的`selection_evidence`绑定。状态必须从0连续编号，全部覆盖编译状态，不允许跳过中间动作。模板见`examples/scene-comparison.template.json`。

选择原生区间应先于候选合成。插画代表选择整个稳定显示窗口，明确排除淡入和返家菜单；地图代表选择完整的一组输入及释放，保留所有中间帧。条件可通过源码与实录分析得到，但不能称作恢复了当时的真实运行状态或RNG。

之后使用README中的同一`pipeline --request ... --output ...`，播放前使用同一请求执行`--playback-directory`。默认有差异就拒绝播放；研究差异时可显式使用`--allow-differences`，不会改变像素门槛。

## 显示中途更新与调色板

BNK图块是四平面、每平面按行储存；PT1则按字节列储存，不能混用解码器。地图的基本显存更新依源码按图块行列顺序、平面、像素行和字节写入。

本次东部步行有一帧在更新中被SVGA读取。固定DOSBox Pure的`vga_draw.cpp`按四段读取480行画面，读取可与游戏写入交错。`source_incremental_map_scanout`因此只拟合单调前进的源码写入进度，四段像素都来自前后两幅源码合成状态；不把实录像素粘贴到合成画面。必须绑定对应核心、SVGA/S3配置和固定`scanout_source`文件哈希，并且该帧前后实录须分别匹配相邻源码状态。不满足时保留差异。一般`source_incremental_map_tiles`仅尝试一次显存快照；两种模型都不推算CPU/显卡时间。

东部昼夜变化目前接收显式`observed_native_palette_trace`输入：`entries`提供基本RGB16，`changes`记录`first_frame/entries`。这是颜色条件，不是源码调色板时序预测。稀少颜色不能仅用移动人物上的单个像素校准；本次用179个固定界面参考点核对颜色10，全部一致。未观测且不参与输出的色槽必须说明来源，不能宣称全部寄存器已恢复。
